## Executive summary

- **Customer web is `/shop/*` inside `vendor-dashboard`**, not a separate Next.js app. Vendor desk (`/`, `/products`, `/orders`, …) shares origin, `AuthGuard`, and persist key `vendor-auth`.
- **`admin-panel`** is a six-page Next.js desk plus `/login`. Same fixed sidebar + remapped `bg-white` tables as vendor ops pages.
- **Responsive:** Mall `GuestChrome` is one horizontal header; listing grids are `grid-cols-4` / checkout `grid-cols-2` / footer `grid-cols-4` with almost no breakpoints. Vendor and admin shells keep a permanent `w-64` sidebar.
- **Auth:** Mall chrome never reads the session (Join/Sign in always). Shopper footer/sell links hit `/advertise`, `/fees`, `/verify`, which are not public — `AuthGuard` sends people to merchant `/login`.
- **Sell → dashboard:** `/shop/sell` registers a vendor then `router.replace('/')` into the vendor desk. A second create-store UI lives at `/signup`. Desk URLs remain in shopper footer.
- **Admin flows:** Users/vendors lack empty/error UI; login is unlabelled with seed passwords; settings can save before fetch; dashboard zeros look like real stats if the query fails.
- **Neither Next app has `error.tsx` / `not-found.tsx` / `loading.tsx`.** Vendor orders treat `undefined` as “No orders yet.” Product table has no empty copy.
- **Forms:** `htmlFor` appears only on mall search and filter price. Product form still says `Price ($)` while the mall uses `R` / ZAR. Verify “upload” stores a filename.

## Findings

### P0

#### P0-1 — Shopper header, grids, and footer do not adapt below desktop

- **Severity:** P0
- **Title:** Mall chrome and listing grids are desktop-only
- **Affected routes:** `/shop`, `/shop/browse`, `/shop/product/[id]`, `/shop/store/[slug]`, `/shop/saved`, `/shop/checkout`, `/shop/join`, `/shop/sell`, `/shop/gift-cards`, `/shop/vouchers` (all `GuestChrome` / `GuestFooter` pages)
- **Files:** `apps/vendor-dashboard/components/shop/GuestChrome.tsx`, `ShopPromises.tsx`, `GuestFooter.tsx`, `ProductGrid.tsx`, `app/shop/browse/page.tsx`, `app/shop/saved/page.tsx`, `app/shop/store/[slug]/page.tsx`, `app/shop/product/[id]/page.tsx`, `app/shop/checkout/page.tsx`, `app/shop/join/page.tsx`, `app/shop/sell/page.tsx`, `app/shop/gift-cards/page.tsx`, `app/shop/vouchers/page.tsx`
- **Why it matters:** Header is one `flex` row: logo, Deliver to, search, four `shrink-0` promise icons, loved/bag, theme, Join, Sign in. No `md:`/`lg:` hide or overflow menu. Footer is `grid-cols-4`. Browse/saved/store/`ProductGrid` are `grid-cols-4`; checkout/PDP/join/sell are `grid-cols-2`; gift cards/vouchers are `grid-cols-3`. On tablet/phone this overflows or crushes the customer web surface.
- **Suggested fix direction:** Collapsed mall header (search + icon actions; promises/join in a wrap or drawer) and mobile-first grids (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`).

#### P0-2 — Vendor and admin desks have no compact navigation

- **Severity:** P0
- **Title:** Fixed `w-64` sidebar with no mobile pattern
- **Affected routes:** Vendor desk `/`, `/products`, `/orders`, `/studio`, `/advertise`, `/store/settings`, `/fees`, `/verify`; admin `/dashboard`, `/vendors`, `/orders`, `/ads`, `/users`, `/settings`
- **Files:** `apps/vendor-dashboard/components/layout/AppShell.tsx`, `Sidebar.tsx`, `Header.tsx`; `apps/admin-panel/components/layout/AppShell.tsx`, `Sidebar.tsx`, `Header.tsx`; `apps/vendor-dashboard/components/products/ProductTable.tsx`; `apps/admin-panel/app/users/page.tsx`, `vendors/page.tsx`, `ads/page.tsx`
- **Why it matters:** Both shells are `flex h-screen` with a permanent `aside.w-64`. No hamburger, overlay, or `hidden lg:block`. Headers keep email + Sign out on one row. Product and admin tables are `w-full` without `overflow-x-auto`.
- **Suggested fix direction:** Breakpoint-collapsed labelled menu; wrap tables or switch to stacked cards on small screens.

#### P0-3 — Shopper chrome ignores session

- **Severity:** P0
- **Title:** Logged-in shoppers still see Join and Sign in
- **Affected routes:** Every `GuestChrome` page
- **Files:** `apps/vendor-dashboard/components/shop/GuestChrome.tsx`, `stores/authStore.ts` (persist key `vendor-auth`)
- **Why it matters:** `/shop/login` and `/shop/signup` call `setSession`, but mall chrome always renders Join + Sign in. No account menu, orders entry, or sign-out. Session is stored under `vendor-auth` on the vendor app origin.
- **Suggested fix direction:** Branch header on `useAuthStore` (account / sign out); keep guest CTAs only when `token` is missing.

#### P0-4 — Sell → dashboard and shopper links into vendor-auth

- **Severity:** P0
- **Title:** Shopper IA leaks desk URLs; sell handoff is split across two signups
- **Affected routes:** `/shop` (footer), `/shop/sell`, `/signup`
- **Files:** `apps/vendor-dashboard/components/shop/GuestFooter.tsx` (`/advertise`, `/fees`, `/login`, `/verify`); `app/shop/sell/page.tsx` (`Link href="/fees"`, `router.replace('/')` after `registerVendor`); `app/signup/page.tsx`; `lib/publicPaths.ts`; `components/auth/AuthGuard.tsx`
- **Why it matters:** `/shop/sell` creates a merchant and sends them to vendor `/` (desk). Shoppers still see Advertise, Fees, and Seller verification in mall chrome. Those paths are not in `isPublicPath`. Unauthenticated clicks land on merchant `/login`; a `CUSTOMER` session is redirected to `/shop`. `/signup` is a second create-store UI (`AuthChrome`) next to `/shop/sell` (`GuestChrome`). Footer “PayGate checkout” and “Safe & secure” both `href="/shop"`.
- **Suggested fix direction:** One sell path into the desk after auth; keep desk URLs out of shopper footer; public fee/trust copy for guests.

### P1

#### P1-1 — No App Router error, 404, or loading UI

- **Severity:** P1
- **Title:** Missing `error.tsx` / `not-found.tsx` / `loading.tsx` on both Next apps
- **Affected routes:** Unknown paths and thrown render errors in vendor-dashboard and admin-panel
- **Files:** None under `apps/vendor-dashboard/app/**` or `apps/admin-panel/app/**`. Layouts: `apps/vendor-dashboard/app/layout.tsx`, `apps/admin-panel/app/layout.tsx`
- **Why it matters:** Typos and unknown URLs get the framework default 404, not mall/admin chrome. Auth wait is one line (`Checking session...` / `Verifying access...`) with no timeout.
- **Suggested fix direction:** Branded `not-found` and `error` per app (and `/shop` segment), with home + retry.

#### P1-2 — Vendor orders loading looks empty; products have no empty UI

- **Severity:** P1
- **Title:** `undefined` list data is treated as an empty store
- **Affected routes:** `/orders`, `/products`
- **Files:** `apps/vendor-dashboard/app/orders/page.tsx` (no `isLoading` / `isError`); `components/orders/OrderList.tsx` (`if (!orders?.length)` → “No orders yet.”); `app/products/page.tsx` + `components/products/ProductTable.tsx` (no loading/empty/error; empty `<tbody>`)
- **Why it matters:** Empty copy **exists** on orders. The hole is pending/failed queries looking identical to a healthy empty list. Products show headers and no rows with no message.
- **Suggested fix direction:** Pending / error / empty branches before list chrome.

#### P1-3 — Admin users, vendors, and dashboard error/empty holes

- **Severity:** P1
- **Title:** Admin list/dashboard queries have no empty or failure UI
- **Affected routes:** `/users`, `/vendors`, `/dashboard`
- **Files:** `apps/admin-panel/app/users/page.tsx`, `app/vendors/page.tsx`, `app/dashboard/page.tsx` (`isLoading` only; zeros if `stats` missing)
- **Why it matters:** Empty tenant or failed API is a headered table with no rows, or `R0.00` / `0`, with no retry. Ads already has “No campaigns yet.”
- **Suggested fix direction:** Empty copy + visible `isError` + retry. Treat dashboard zeros as unverified if the query failed (QA).

#### P1-4 — Most forms lack associated labels

- **Severity:** P1
- **Title:** Labels are visual-only or missing; inputs rely on placeholders
- **Affected routes:** Admin `/login`; vendor `/signup`, `/shop/signup`, `/shop/sell`, `/shop/checkout`, `/verify`, `/advertise`, `/studio`, `/store/settings`, `/products` (modal); admin `/settings`
- **Files:** `apps/admin-panel/app/login/page.tsx` (unlabelled fields, initial `admin@shopping-mall.local` / `Password123!`); `apps/vendor-dashboard/app/signup/page.tsx`; `app/shop/sell/page.tsx`; `app/shop/signup/page.tsx`; `app/shop/checkout/page.tsx`; `app/verify/page.tsx`; `app/advertise/page.tsx`; `components/products/ProductForm.tsx`; `app/store/settings/page.tsx`; `apps/admin-panel/app/settings/page.tsx`; `components/auth/AuthMethods.tsx` (OTP)
- **Why it matters:** `htmlFor` appears only on mall search and filter price. Admin login is two unnamed inputs with seed credentials in state.
- **Suggested fix direction:** Visible/`htmlFor` labels on every control; do not ship prefilled admin passwords in the UI.

#### P1-5 — Product form currency contradicts the mall

- **Severity:** P1
- **Title:** Add/Edit Product still says “Price ($)”
- **Affected routes:** `/products`
- **Files:** `apps/vendor-dashboard/components/products/ProductForm.tsx` (`Price ($) *`, `Compare Price ($)`); `ProductTable.tsx` (`R{product.price}`); `GuestChrome.tsx` `money()` (`R…`)
- **Why it matters:** Desk and mall are ZAR. The create/edit form implies USD.
- **Suggested fix direction:** Label from platform currency (pricing settings), not a hardcoded `$`.

#### P1-6 — Desk visual language is two systems

- **Severity:** P1
- **Title:** `mm-card` vs remapped `bg-white` ops pages
- **Affected routes:** Vendor `/` vs `/products`, `/orders`, `/studio`, `/advertise`, `/fees`, `/store/settings`; admin `/dashboard` vs `/users`, `/vendors`, `/ads`, `/orders`, `/settings`
- **Files:** `packages/config/css/mmall.css` (`.bg-white { background-color: var(--mm-card) !important }`); vendor `app/page.tsx`; `ProductTable.tsx`; `OrderList.tsx`; `app/studio/page.tsx`; `apps/admin-panel/app/users/page.tsx`; `AuthMethods.tsx` (`bg-white text-[#1f1f1f]` on Google)
- **Why it matters:** Overview is glass `mm-card`. Ops pages still use `rounded-lg shadow` / `bg-blue-600`. The global `.bg-white` override can make the Google button dark-on-dark in dark mode.
- **Suggested fix direction:** One desk card/button pattern; stop using `!important` aliases for contrast.

#### P1-7 — Interstitial ad on checkout, bag, and help

- **Severity:** P1
- **Title:** `AdPopup` is not excluded from purchase paths
- **Affected routes:** `/shop/*` except `/shop/login`, `/shop/signup`, `/shop/join`, `/shop/sell`, `/shop/legal/*`
- **Files:** `apps/vendor-dashboard/app/shop/layout.tsx`; `components/shop/AdPopup.tsx` (`FIRST_MS = 8000`, `EVERY_MS = 40000`)
- **Why it matters:** Overlay 8s after load, then every 40s, including `/shop/checkout` and `/shop/bag`. Escape exists; Tab is not trapped.
- **Suggested fix direction:** Exclude checkout/bag/help; cap frequency; trap focus.

#### P1-8 — Help, returns, and bag line items are dead ends

- **Severity:** P1
- **Title:** Customer service copy and basket controls do not match routes
- **Affected routes:** `/shop/help`, `/shop/bag`
- **Files:** `apps/vendor-dashboard/app/shop/help/page.tsx` (contact `setSent(true)` only; `orders.isError` → “No live orders on this account yet.”; returns: “Start a return from the order once it is delivered”); no `app/shop/orders`. `app/shop/bag/page.tsx` (Clear basket only)
- **Why it matters:** Contact does not call an API. Failed order fetch looks empty. Footer “Track an order” is `#orders` on help. Basket lines cannot be adjusted without clearing all.
- **Suggested fix direction:** Honest error/empty copy; don’t promise returns until a route exists; per-line bag qty/remove.

#### P1-9 — KYC upload UI stores filenames only

- **Severity:** P1
- **Title:** Verify shows “Uploaded: {filename}” without sending a file
- **Affected routes:** `/verify`
- **Files:** `apps/vendor-dashboard/app/verify/page.tsx` (`FileDrop` `onFile(file.name)`; getUserMedia failure sets `selfieCaptured: true`; “Use demo liveness capture”)
- **Why it matters:** Highest-stakes vendor flow looks like an upload. Submit payload is names/strings. Camera failure is silent success.
- **Suggested fix direction:** Upload bytes with progress/error, or label the control as demo-only; real `<label>`s on every field.

#### P1-10 — Overlays without focus trap; unnamed icon controls

- **Severity:** P1
- **Title:** Filter, ad, deliver-to, product, gift-card, and voucher dialogs are incomplete modals
- **Affected routes:** `/shop` (filters, ads, deliver to), `/products` (form), `/shop/gift-cards`, `/shop/vouchers`
- **Files:** `components/shop/FilterBar.tsx`; `AdPopup.tsx`; `DeliverTo.tsx` (no `role="dialog"`, no Escape, unlabelled search); `components/products/ProductForm.tsx` (image remove `×` with no `aria-label`)
- **Why it matters:** Tab can leave the overlay. Deliver-to search is placeholder-only.
- **Suggested fix direction:** Focus trap, Escape, labelled close on every overlay.

#### P1-11 — Duplicate merchant signup; unused home components

- **Severity:** P1
- **Title:** Two create-store UIs; banner/category never mounted
- **Affected routes:** `/signup` vs `/shop/sell`; `/shop`
- **Files:** `apps/vendor-dashboard/app/signup/page.tsx`; `app/shop/sell/page.tsx`; `components/shop/GuestHeroBanner.tsx` and `CategoryStrip.tsx` (no page imports)
- **Why it matters:** Join → sell uses `/shop/sell`; merchant “Create a free store” uses `/signup`. Home never renders the banner or department strip that exist in code.
- **Suggested fix direction:** One merchant registration path into the desk; mount or delete unused home pieces.

- **Affected routes:** `/products`, `/users`

#### P2-3 — Store and browse degrade silently

- **Severity:** P2
