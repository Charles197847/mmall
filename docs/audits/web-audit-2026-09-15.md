## Executive summary

- **Highest risk is the vendor desk, not mall chrome.** `/shop/sell` and `/signup` both `router.replace('/')` (Store pulse). A new merchant never lands on `/products` (list) or `/orders`.
- **Auth is fragile on refresh.** `AuthGuard` / `AdminGuard` read a persist store with no `hasHydrated`. First client paint is `token=null` → `replace('/login')`. Shopper footer and vendor Terms “fee schedule” point at `/fees`, `/advertise`, `/verify`, which are not public.
- **Empty vs error vs loading is wrong on the two desks the vendor uses most.** `/orders` has empty copy but treats `undefined` as empty. `/products` has no empty/error UI. Overview can show `R0.00` / `0` while `useVendor` has not resolved (`analytics` `enabled: Boolean(vendor)` → TanStack `isLoading` false).
- **Vendor and admin shells are not responsive.** Permanent `w-64` sidebar; tables without `overflow-x-auto`.
- **Admin IA:** Sidebar routes all exist (`/dashboard` `/vendors` `/orders` `/ads` `/users` `/settings`). `/` redirects to `/dashboard`. There is no branded 404. Users/vendors have no empty/error. Vendors “Category rates” is a full-page `<a href="/settings">`, not a missing route.
- **Customer web is `/shop/*` inside vendor-dashboard.** Demoted vs desk: header ignores session; grids/header lack breakpoints. Expo skipped.

## Findings

Findings follow Lead order: vendor-dashboard, then admin-panel, then `/shop`.

### 1) vendor-dashboard

#### P0 — Sell does not land on list or orders

- **Severity:** P0
- **Title:** Post-sell handoff is Overview, not catalog or orders
- **Affected routes:** `/shop/sell`, `/signup`, `/`, `/products`, `/orders`
- **Files:** `apps/vendor-dashboard/app/shop/sell/page.tsx` (`setSession` then `router.replace('/')`); `app/signup/page.tsx` (same `replace('/')`); `app/page.tsx`; `components/layout/Sidebar.tsx` (Overview `/`, Products `/products`, Orders `/orders`)
- **Why it matters:** A new merchant finishes sell/signup on Store pulse (analytics zeros). They must discover Products to list and Orders to fulfil. Two create-store UIs (`GuestChrome` vs `AuthChrome`) do the same handoff. Vendor Terms “fee schedule” is `href="/fees"` (`TermsAccept.tsx`) while `/fees` is not public — mid-signup click hits `AuthGuard` → `/login`.
- **Suggested fix direction:** One sell path; land on `/products` (empty list) or a first-listing prompt; public fees during signup.

#### P0 — AuthGuard redirects before persist rehydrates

- **Severity:** P0
- **Title:** Desk session looks logged-out on first paint
- **Affected routes:** All non-public vendor routes (`/`, `/products`, `/orders`, …)
- **Files:** `components/auth/AuthGuard.tsx` (`if (!token || !user) router.replace('/login')`); `stores/authStore.ts` (`persist`, name `vendor-auth`, no `onRehydrateStorage` / `hasHydrated`)
- **Why it matters:** Zustand persist is async. SSR and the first client effect see `token=null`, show “Checking session...”, then send a logged-in vendor to `/login`. Refresh on `/orders` or `/products` is unsafe. `requiredRole="VENDOR"` also sends `CUSTOMER` to `/shop`.
- **Suggested fix direction:** Wait for persist rehydration before redirect; keep a real signed-in shell.

#### P0 — Vendor shell is not responsive

- **Severity:** P0
- **Title:** Fixed `w-64` sidebar; tables clip
- **Affected routes:** `/`, `/products`, `/orders`, `/studio`, `/advertise`, `/store/settings`, `/fees`, `/verify`
- **Files:** `components/layout/AppShell.tsx`, `Sidebar.tsx`, `Header.tsx`; `components/products/ProductTable.tsx`; `components/orders/OrderList.tsx`
- **Why it matters:** `flex h-screen` + permanent `aside.w-64`. No `hidden lg:block`, overlay, or labelled menu. Product table is `w-full` with no `overflow-x-auto`. This is the desk a seller hits after sell.
- **Suggested fix direction:** Collapse sidebar below a breakpoint; wrap tables or use stacked rows.

#### P0 — `/orders` loading and error look like an empty store

- **Severity:** P0
- **Title:** “No orders yet” is shown when data has not arrived
- **Affected routes:** `/orders`
- **Files:** `app/orders/page.tsx` (passes `orders` with no `isLoading`/`isError`); `components/orders/OrderList.tsx` (`if (!orders?.length)` → “No orders yet.”)
- **Why it matters:** Empty copy **is implemented**. `undefined` (pending) and `[]` (none) and a failed query (still undefined) all hit the same branch. After sell, the first visit to Orders can look like “no business” while the list is still fetching.
- **Suggested fix direction:** Pending / error / empty as three states. QA: confirm failed `vendors.orders.list` vs true empty.

#### P1 — `/products` has no empty or error UI

- **Severity:** P1
- **Title:** Product table is headers plus blank body
- **Affected routes:** `/products`
- **Files:** `app/products/page.tsx`; `components/products/ProductTable.tsx`
- **Why it matters:** New seller listing (the actual “list” step) has no “No products yet” and no fetch error. Delete is unconfirmed (`<button>Delete</button>` → `mutate`).
- **Suggested fix direction:** Empty CTA to add product; loading/error; confirm delete.

#### P1 — Overview zeros while vendor profile is still loading

- **Severity:** P1
- **Title:** Store pulse can look like a live zero dashboard
- **Affected routes:** `/`
- **Files:** `app/page.tsx`; `hooks/useVendor.ts` (`api.auth.me()`); analytics `enabled: Boolean(vendor)`, then `if (isLoading)` only
- **Why it matters:** Disabled TanStack queries are not `isLoading`. Until `vendor` exists, the page can render `R0.00` / `0` products / `0` orders with an empty chart (`salesTrend ?? []`). Same screen sell lands on.
- **Suggested fix direction:** Gate on `useVendor().isLoading` and analytics `isError`; don’t treat missing stats as zero.

#### P1 — No App Router error/404/loading

- **Severity:** P1
- **Title:** Unknown vendor URLs and render errors are unbranded
- **Affected routes:** Any unmatched path under vendor-dashboard
- **Files:** no `error.tsx` / `not-found.tsx` / `loading.tsx` under `apps/vendor-dashboard/app/`
- **Why it matters:** Typo `/order` vs `/orders` leaves the desk chrome.
- **Suggested fix direction:** Desk-branded `not-found` + `error` with link to `/` and `/products`.

#### P1 — Role routing allows vendor onto mall paths

- **Severity:** P1
- **Title:** `safeNext` barely restricts `/shop` for VENDOR
- **Affected routes:** `/login`, `/shop/*`
- **Files:** `lib/finishAuth.ts`; `app/login/page.tsx` (CUSTOMER → `/shop`)
- **Why it matters:** The VENDOR guard only rejects paths that start with `/shop` but are not `/shop` and not `/shop/…` (almost none). A `next=/shop/bag` stays on the mall with a vendor session. Desk and mall share `vendor-auth`.
- **Suggested fix direction:** Send VENDOR `next` under `/shop` to `/` (or `/products`) unless explicitly previewing the store.

#### P1 — Product form currency and overlay a11y

- **Severity:** P1
- **Title:** `$` labels; unnamed remove; no focus trap
- **Affected routes:** `/products`
- **Files:** `components/products/ProductForm.tsx`
- **Why it matters:** Table uses `R`. Form says `Price ($)`. Overlay is `fixed inset-0` without trap; remove control is `×` with no `aria-label`. Most desk fields (signup, verify, advertise, settings) lack `htmlFor` (only mall search/filter price have it).
- **Suggested fix direction:** ZAR labels; labelled modal; labels on desk fields.

#### P1 — Verify “upload” is a filename

- **Severity:** P1
- **Title:** KYC FileDrop never sends bytes
- **Affected routes:** `/verify`
- **Files:** `app/verify/page.tsx` (`onFile(file.name)`; getUserMedia catch sets `selfieCaptured: true`)
- **Why it matters:** UI says “Uploaded: {name}”. Submit is strings. Camera failure is silent success.
- **Suggested fix direction:** Upload bytes with error/progress, or mark demo-only. Backend for storage contract.

### 2) admin-panel

#### P0 — AdminGuard same persist bounce

- **Severity:** P0
- **Title:** Admin session redirect races rehydration
- **Affected routes:** `/dashboard`, `/vendors`, `/orders`, `/ads`, `/users`, `/settings`
- **Files:** `apps/admin-panel/components/auth/AdminGuard.tsx`; `stores/authStore.ts` (`admin-auth`)
- **Why it matters:** Same pattern as vendor: `!authorized` → spinner then `replace('/login')` before persist. Core admin IA is unreachable on refresh if the race hits.
- **Suggested fix direction:** Same rehydration gate as vendor.

#### P1 — Admin shell not responsive; unbranded 404

- **Severity:** P1
- **Title:** Fixed sidebar; no `not-found`
- **Affected routes:** All authenticated admin routes; any unknown path
- **Files:** `components/layout/AppShell.tsx`, `Sidebar.tsx`; `app/layout.tsx` (no `not-found.tsx`)
- **Why it matters:** Sidebar hrefs (`/dashboard` `/vendors` `/orders` `/ads` `/users` `/settings`) all have pages — **no dead named nav item**. `/` correctly `redirect('/dashboard')`. Broken-route risk is unmatched URLs (default Next 404, no control-plane chrome) and small-viewport clip.
- **Suggested fix direction:** Compact nav; branded `not-found` to `/dashboard`.

#### P1 — Users and vendors lists have no empty/error

- **Severity:** P1
- **Title:** Headered tables with zero rows; no `isError`
- **Affected routes:** `/users`, `/vendors`
- **Files:** `app/users/page.tsx`, `app/vendors/page.tsx` (`isLoading` spinner only)
- **Why it matters:** Empty tenant vs failed `admin.users.list` / `admin.vendors.list` look the same. Ads/orders already have empty copy. Vendors “Category rates” is `<a href="/settings">` (full reload, route **exists**).
- **Suggested fix direction:** Empty + error + retry; use `Link` for settings.

#### P1 — Admin login unlabelled with seed passwords

- **Severity:** P1
- **Title:** Two unnamed inputs, prefilled seed user
- **Affected routes:** `/login`
- **Files:** `app/login/page.tsx` (`admin@shopping-mall.local`, `Password123!`)
- **Why it matters:** Only public admin screen. No `<label>`. Credentials in initial state.
- **Suggested fix direction:** Labels; empty fields in non-dev builds.

#### P2 — Settings save-before-load; dashboard zeros; role mutate

- **Severity:** P2
- **Title:** Admin ops can persist fallbacks or look healthy when failed
- **Affected routes:** `/settings`, `/dashboard`, `/users`
- **Files:** `app/settings/page.tsx` (`emptySettings` until GET); `app/dashboard/page.tsx`; `app/users/page.tsx` (role `<select>` including `ADMIN`)
- **Why it matters:** Fast Save writes hardcoded fees. Failed stats look like `R0.00`. Role change is one click (vendor Suspend does `confirm`).
- **Suggested fix direction:** Disable settings until loaded; dashboard `isError`; confirm role changes. QA on dashboard zeros.

### 3) customer web (`/shop` in vendor-dashboard)

#### P1 — Mall chrome desktop-only and session-blind

- **Severity:** P1
- **Title:** `GuestChrome` never reads auth; header/grids lack breakpoints
- **Affected routes:** All `GuestChrome` pages
- **Files:** `components/shop/GuestChrome.tsx`; `GuestFooter.tsx`; `ProductGrid.tsx`; `app/shop/browse/page.tsx`; `app/shop/checkout/page.tsx` (`grid-cols-2`); `app/shop/join/page.tsx`
- **Why it matters:** Join/Sign in always. Header is one `flex` row (logo, Deliver to, search, four promises, bag, theme, CTAs). Footer `grid-cols-4`; listings `grid-cols-4`. Third priority vs desk, but this is the in-repo customer web.
- **Suggested fix direction:** Session-aware header; mobile-first grids; stacked footer.

#### P1 — Shopper links into vendor-auth routes

- **Severity:** P1
- **Title:** Footer Advertise/Fees/Verify are not public
- **Affected routes:** `/shop` (footer on all mall pages), `/shop/sell` (`/fees`)
- **Files:** `components/shop/GuestFooter.tsx`; `lib/publicPaths.ts`; `AuthGuard.tsx`
- **Why it matters:** Unauthenticated click → merchant `/login`. `CUSTOMER` → `/shop`. Trust labels “PayGate checkout” and “Safe & secure” both `href="/shop"`.
- **Suggested fix direction:** Public copy for fees/trust; desk URLs only after vendor session.

#### P2 — Checkout ad, help dead ends, bag, soft 404s

- **Severity:** P2
- **Title:** Purchase and support paths have holes; unknown store is not 404
- **Affected routes:** `/shop/checkout`, `/shop/bag`, `/shop/help`, `/shop/store/[slug]`, `/shop/browse`
- **Files:** `app/shop/layout.tsx` + `AdPopup.tsx` (`FIRST_MS = 8000`, `EVERY_MS = 40000`, excluded only login/signup/join/sell/legal); `app/shop/help/page.tsx`; `app/shop/bag/page.tsx`; `app/shop/store/[slug]/page.tsx` (`storeName ?? 'Store'`); `app/shop/browse/page.tsx`
- **Why it matters:** Ad overlay on checkout. Help contact is `setSent(true)`; `orders.isError` copy is “No live orders…”. No `/shop/orders`. Bag cannot change qty per line. Bad slug still says “Store”. Browse has no zero-results line.
- **Suggested fix direction:** Exclude checkout from ads; honest help/error; line-item bag; store not-found.

`GuestHeroBanner.tsx` and `CategoryStrip.tsx` are never imported by a page (unused, not a user-facing screen).
