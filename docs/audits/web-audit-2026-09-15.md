# M-MALL web UI/UX audit

**Date:** 2026-09-15  
**Scope:** Next.js surfaces in this monorepo (`vendor-dashboard`, `admin-panel`, and the shopper mall hosted inside `vendor-dashboard`).  
**Out of scope:** Native Expo screens in `apps/customer-app`, except a short map note (that app can export web, but it is React Native / Expo Router, not Next.js). No product code was changed for this audit.

Evidence is from route files and components in the repo. Screens that are not implemented were not invented.

---

## Executive summary

- The **primary shopper web surface is not a separate Next.js app**. It lives at `/shop/*` inside `apps/vendor-dashboard` (Next.js App Router, port 3001). Vendor desk routes (`/`, `/products`, `/orders`, …) share the same origin and auth store (`vendor-auth`).
- **`apps/admin-panel`** is a smaller Next.js App Router app (port 3002) with six authenticated pages plus `/login`. Layout and table patterns closely copy the vendor desk.
- **`apps/customer-app`** is Expo (web + iOS + Android). It is the README’s “customer app” and duplicates mall/vendor IA, but it is not a Next.js surface. `@shopping-mall/shared-ui` is React Native-only and is **not** used by the Next.js apps.
- **Neither Next.js app defines `error.tsx`, `not-found.tsx`, or `loading.tsx`.** Failed or unknown routes fall through to Next.js defaults. Several data pages treat `undefined` query results as empty lists.
- **Shopper chrome does not collapse.** `GuestChrome` is a single horizontal header (logo, Deliver to, search, four promise icons, bag/loved, theme, Join, Sign in). Product/browse/saved/store grids are hardcoded `grid-cols-4`; checkout, PDP, and join are `grid-cols-2`; footer is `grid-cols-4`. Almost none of these have `sm`/`md` breakpoints.
- **Vendor and admin desks have no mobile navigation.** Both use a fixed `w-64` sidebar with no hamburger, overlay, or stacked header. Wide tables (`ProductTable`, admin users/vendors/ads) have no `overflow-x-auto`.
- **Role bleed is visible in the shopper footer and sell flow.** Shopper links go to vendor-auth routes (`/advertise`, `/fees`, `/verify`). `isPublicPath` only allows `/login`, `/signup`, and `/shop*`, so those links hit `AuthGuard` and bounce to merchant login.
- **Signed-in shoppers still see Join / Sign in.** `GuestChrome` never reads `useAuthStore`. There is no shopper account menu, orders route, or sign-out in mall chrome. Help copy promises returns and tracking that have no routes.
- **Forms are uneven.** Shop search and filter price fields have `sr-only` labels. Most vendor, admin, checkout, signup, and KYC fields use placeholders only (no `htmlFor`). Admin login has no labels at all and ships prefilled credentials.
- **Visual system is split.** Overview/dashboard uses `mm-card` navy glass; products, orders, studio, advertise, fees, and most admin list pages use remapped `bg-white` “bootstrap” cards. Product form still labels price as `$` while the rest of the mall uses `R` / ZAR.

## Findings

### P0

#### P0-1 — Shopper header, grids, and footer do not adapt below desktop

- **Severity:** P0
- **Title:** Mall chrome and listing grids are desktop-only
- **Affected routes:** `/shop`, `/shop/browse`, `/shop/product/[id]`, `/shop/store/[slug]`, `/shop/saved`, `/shop/checkout`, `/shop/join`, `/shop/sell`, `/shop/gift-cards`, `/shop/vouchers`, all shop pages using `GuestChrome` / `GuestFooter`
- **Files:** `components/shop/GuestChrome.tsx`, `components/shop/ShopPromises.tsx`, `components/shop/GuestFooter.tsx`, `components/shop/ProductGrid.tsx`, `app/shop/browse/page.tsx`, `app/shop/saved/page.tsx`, `app/shop/store/[slug]/page.tsx`, `app/shop/product/[id]/page.tsx`, `app/shop/checkout/page.tsx`, `app/shop/join/page.tsx`, `app/shop/sell/page.tsx`, `app/shop/gift-cards/page.tsx`, `app/shop/vouchers/page.tsx`
- **Why it matters:** The header is one `flex` row with logo, Deliver to, search (`flex-1`), four labelled promise icons (`shrink-0`), loved/bag, theme, Join, and Sign in. There is no `md:`/`lg:` hide, wrap, or overflow menu. Footer is `grid-cols-4` with no breakpoint. Browse/saved/store/ProductGrid are `grid-cols-4`; checkout/PDP/join/sell are `grid-cols-2`; gift cards/vouchers are `grid-cols-3`. On tablet/phone this will overflow, crush type, or force horizontal scroll on the main shopping surface.
- **Suggested fix direction:** Introduce a stacked/collapsed mall header (search + icon actions; promises and join in a drawer or wrap), and give listing/checkout grids mobile-first columns (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`, etc.).

#### P0-2 — Vendor and admin desks have no compact navigation

- **Severity:** P0
- **Title:** Fixed `w-64` sidebar with no mobile pattern
- **Affected routes:** All authenticated vendor desk routes (`/`, `/products`, `/orders`, `/studio`, `/advertise`, `/store/settings`, `/fees`, `/verify`) and all authenticated admin routes (`/dashboard`, `/vendors`, `/orders`, `/ads`, `/users`, `/settings`)
- **Files:** `apps/vendor-dashboard/components/layout/AppShell.tsx`, `Sidebar.tsx`, `Header.tsx`; `apps/admin-panel/components/layout/AppShell.tsx`, `Sidebar.tsx`, `Header.tsx`; `components/products/ProductTable.tsx`; `apps/admin-panel/app/users/page.tsx`, `vendors/page.tsx`, `ads/page.tsx`
- **Why it matters:** Both shells are `flex h-screen` with a permanent `aside.w-64`. No hamburger, off-canvas nav, or `hidden lg:block`. Headers put email + Sign out + theme on one row. Product and admin tables are `w-full` without a horizontal scroll wrapper. On a phone the sidebar consumes most of the width and tables clip.
- **Suggested fix direction:** Collapse the sidebar below a breakpoint into a labelled menu button, and wrap tables in `overflow-x-auto` (or card rows on small screens).

#### P0-3 — Shopper chrome ignores session; Join/Sign in never become an account

- **Severity:** P0
- **Title:** Logged-in shoppers still see Join and Sign in
- **Affected routes:** Every `GuestChrome` page (`/shop/*` except auth chrome pages)
- **Files:** `components/shop/GuestChrome.tsx`, `stores/authStore.ts` (persist key `vendor-auth`), `app/shop/help/page.tsx`
- **Why it matters:** After `/shop/login` or `/shop/signup`, `setSession` stores the user, but mall chrome always renders Join + Sign in. There is no name, orders, profile, or sign-out in the header. Shoppers cannot tell they are signed in except on `/shop/help`. The store name `vendor-auth` also implies shopper session is bolted onto the vendor app.
- **Suggested fix direction:** Branch header actions on `useAuthStore` (account menu / sign out / help), and keep guest CTAs only when `token` is missing.

#### P0-4 — Shopper footer and sell copy send people into vendor-auth routes

- **Severity:** P0
- **Title:** Shopper IA leaks vendor desk URLs that `AuthGuard` will bounce
- **Affected routes:** `/shop` (footer on all mall pages), `/shop/sell`
- **Files:** `components/shop/GuestFooter.tsx` (links to `/advertise`, `/fees`, `/login`, `/verify`); `app/shop/sell/page.tsx` (`Link href="/fees"`); `lib/publicPaths.ts`; `components/auth/AuthGuard.tsx`
- **Why it matters:** Footer “Sell on MMall” includes Advertise and Fees, and Trust includes Seller verification. Those paths are **not** public. Unauthenticated shoppers land on merchant `/login`. Authenticated customers are redirected to `/shop`. “PayGate checkout” and “Safe & secure” both `href="/shop"` (same destination, unrelated labels). Shoppers cannot read fees without a vendor session.
- **Suggested fix direction:** Point shopper-facing fee/trust links at public copy (e.g. legal or a public fees page), and only expose `/advertise` / `/verify` after merchant auth.

### P1

#### P1-1 — No App Router error, 404, or loading UI

- **Severity:** P1
- **Title:** Missing `error.tsx` / `not-found.tsx` / `loading.tsx` on both Next apps
- **Affected routes:** Any unknown path; any thrown render error in vendor-dashboard or admin-panel
- **Files:** No matches under `apps/vendor-dashboard/app/**` or `apps/admin-panel/app/**` for those filenames. Layouts: `apps/vendor-dashboard/app/layout.tsx`, `apps/admin-panel/app/layout.tsx`
- **Why it matters:** Unknown URLs (typos, stale product ids without a mock fallback) get the framework default 404, not mall/admin chrome. Uncaught errors have no branded recovery. Auth wait states are one-line (`Checking session...` / `Verifying access...`) with no timeout/error.
- **Suggested fix direction:** Add branded `not-found` and `error` boundaries per app (and optionally per `/shop` segment), with a path home and retry.

#### P1-2 — Loading vs empty conflated on vendor orders (and similar lists)

- **Severity:** P1
- **Title:** Orders show “No orders yet” while the query is still loading
- **Affected routes:** `/orders` (vendor); similar pattern on `/products`
- **Files:** `app/orders/page.tsx` (query result passed through with no `isLoading`); `components/orders/OrderList.tsx` (`if (!orders?.length)` → “No orders yet.”); `app/products/page.tsx` + `components/products/ProductTable.tsx` (no loading/empty/error; empty `<tbody>`)
- **Why it matters:** `undefined` and `[]` look the same. A slow or failed API looks like a healthy empty store. Product table has no empty copy at all.
- **Suggested fix direction:** Distinguish pending / error / empty in the query consumers before rendering the list chrome.

#### P1-3 — Admin list pages missing empty and error states

- **Severity:** P1
- **Title:** Users and vendors tables have no empty copy; queries have no `isError` UI
- **Affected routes:** `/users`, `/vendors`; also `/dashboard` if `admin.stats` fails
- **Files:** `apps/admin-panel/app/users/page.tsx`, `app/vendors/page.tsx`, `app/dashboard/page.tsx` (`isLoading` only; zeros if `stats` is missing)
- **Why it matters:** An empty tenant or a failed admin API renders a headered table with no rows, or a dashboard of `R0.00` / `0`, with no retry. Operators cannot tell “none” from “broken”.
- **Suggested fix direction:** Add empty rows and a visible query-error + retry on these pages. Ads already has “No campaigns yet.”

#### P1-4 — Most forms lack associated labels

- **Severity:** P1
- **Title:** Labels are visual-only or missing; inputs rely on placeholders
- **Affected routes:** `/login` (admin), `/signup`, `/shop/signup`, `/shop/sell`, `/shop/checkout`, `/verify`, `/advertise`, `/studio`, `/store/settings`, `/products` (modal), `/settings` (admin)
- **Files:** `apps/admin-panel/app/login/page.tsx` (unlabelled email/password, prefilled `admin@shopping-mall.local` / `Password123!`); `app/signup/page.tsx`; `app/shop/sell/page.tsx`; `app/shop/signup/page.tsx`; `app/shop/checkout/page.tsx`; `app/verify/page.tsx`; `app/advertise/page.tsx`; `components/products/ProductForm.tsx`; `app/store/settings/page.tsx`; `apps/admin-panel/app/settings/page.tsx`; `components/auth/AuthMethods.tsx` (OTP field)
- **Why it matters:** Across the Next apps, `htmlFor` appears only on shop search and filter price. Placeholder-only fields disappear when filled; screen readers get unnamed controls. Admin login is the weakest: two inputs, no `<label>`, credentials baked into initial state.
- **Suggested fix direction:** Visible labels (or wrapping `<label>`) on every control; don’t leave production-looking admin fields prefilled with seed passwords.

#### P1-5 — Product form currency contradicts the mall

- **Severity:** P1
- **Title:** Add/Edit Product still says “Price ($)”
- **Affected routes:** `/products`
- **Files:** `components/products/ProductForm.tsx` (labels `Price ($) *` and `Compare Price ($)`); `components/products/ProductTable.tsx` (`R{product.price}`); shop `money()` in `GuestChrome.tsx` (`R…`); admin/vendor dashboards use `R` / `formatMoney` / ZAR
- **Why it matters:** Merchants pricing in rand will assume USD. The rest of the desk and mall is ZAR.
- **Suggested fix direction:** Align the form with platform currency (label + prefix), sourced from pricing settings rather than a hardcoded `$`.

#### P1-6 — Desk visual language is two systems

- **Severity:** P1
- **Title:** `mm-card` navy glass vs remapped `bg-white` bootstrap cards
- **Affected routes:** Vendor `/` vs `/products`, `/orders`, `/studio`, `/advertise`, `/fees`, `/store/settings`; admin `/dashboard` vs `/users`, `/vendors`, `/ads`, `/orders`, `/settings`
- **Files:** `packages/config/css/mmall.css` (`.bg-white { background-color: var(--mm-card) !important }`); `app/page.tsx` (`mm-card`); `components/products/ProductTable.tsx`; `components/orders/OrderList.tsx`; `app/studio/page.tsx`; `apps/admin-panel/app/users/page.tsx` etc.
- **Why it matters:** Overview looks like the mall (rounded glass, `text-ice`). Catalog/ops pages still use `rounded-lg shadow`, `bg-blue-600`, `text-blue-600`, `bg-gray-200` chips. Global CSS remaps some of that, so Google’s `bg-white text-[#1f1f1f]` in `AuthMethods.tsx` can become dark-on-dark in dark mode.
- **Suggested fix direction:** Pick one card/table/button pattern for desk pages (prefer `mm-card` + brand tokens) and stop relying on `!important` Tailwind aliases for contrast.

#### P1-7 — Interstitial ad on checkout, bag, and help

- **Severity:** P1
- **Title:** `AdPopup` fires on almost every shop path, including checkout
- **Affected routes:** `/shop/*` except `/shop/login`, `/shop/signup`, `/shop/join`, `/shop/sell`, `/shop/legal/*`
- **Files:** `app/shop/layout.tsx` (mounts `AdPopup`); `components/shop/AdPopup.tsx` (`FIRST_MS = 8000`, `EVERY_MS = 40000`; no focus trap)
- **Why it matters:** A modal overlay 8s after landing, then every 40s, including on `/shop/checkout` and `/shop/bag`, interrupts a purchase. Escape and a close control exist, but Tab is not trapped. Hostile for keyboard and for conversion.
- **Suggested fix direction:** Exclude checkout/bag/help (and maybe first-run), cap frequency, and trap focus while open.

#### P1-8 — Help and returns are dead ends

- **Severity:** P1
- **Title:** Customer service promises orders, returns, and a contact desk that are not implemented
- **Affected routes:** `/shop/help`, `/shop/bag`
- **Files:** `app/shop/help/page.tsx` (contact `onSubmit` only `setSent(true)`; `orders.isError` rendered as “No live orders on this account yet.”; returns copy: “Start a return from the order once it is delivered”); no `app/shop/orders` route. `app/shop/bag/page.tsx` has Clear basket but no per-line qty or remove.
- **Why it matters:** Contact “saves” locally with no API. Failed order fetch looks empty. There is no order detail, tracking UI, or return UI despite footer “Track an order” → `#orders`. Basket lines cannot be adjusted without clearing everything.
- **Suggested fix direction:** Honest empty/error copy; wire contact or say it’s unavailable; add line-item bag controls; don’t promise returns until a route exists.

#### P1-9 — KYC upload UI stores filenames only

- **Severity:** P1
- **Title:** Verify flow shows “Uploaded: {filename}” without uploading a file
- **Affected routes:** `/verify`
- **Files:** `app/verify/page.tsx` (`FileDrop` `onFile(file.name)` only; camera failure silently sets `selfieCaptured: true`; “Use demo liveness capture”)
- **Why it matters:** The control looks like a document upload. Users get success chrome for a local name string. Combined with unlabelled legal-name / ID / address fields, the highest-stakes form is also one of the least accessible.
- **Suggested fix direction:** Either upload bytes (with progress/error) or label the control as a demo filename, and associate real `<label>`s with every field.

#### P1-10 — Dialogs without focus trap; icon-only controls missing names

- **Severity:** P1
- **Title:** Filter, ad, deliver-to, product, gift-card, and voucher dialogs are incomplete as modal UX
- **Affected routes:** `/shop` (filters, ads, deliver to), `/products` (form overlay), `/shop/gift-cards`, `/shop/vouchers`
- **Files:** `components/shop/FilterBar.tsx` (Escape + initial focus, no Tab cycle); `AdPopup.tsx`; `DeliverTo.tsx` (no `role="dialog"`, no Escape, search input unlabelled); `components/products/ProductForm.tsx` (fixed overlay, image remove is `×` with no `aria-label`); gift/voucher pages use overlay buttons
- **Why it matters:** Keyboard users can tab into the page behind the overlay. Deliver-to search is placeholder-only. Product image remove is an unnamed control.
- **Suggested fix direction:** Standard modal behaviour (focus trap, Escape, labelled close) on every overlay; name the remove button.

#### P1-11 — Duplicate merchant signup and unused mall components

- **Severity:** P1
- **Title:** Two vendor create-store UIs; hero/category components never mounted
- **Affected routes:** `/signup` vs `/shop/sell`; `/shop` home
- **Files:** `app/signup/page.tsx` (`AuthChrome`); `app/shop/sell/page.tsx` (`GuestChrome`, duplicate OTP form); `components/shop/GuestHeroBanner.tsx` and `components/shop/CategoryStrip.tsx` (defined, **zero imports** from pages)
- **Why it matters:** Join → “I want to sell” uses `/shop/sell`, while merchant “Create a free store” uses `/signup`. Copy and chrome differ. Home never shows the banner or department strip that exist in code — a hole relative to the mall metaphor.
- **Suggested fix direction:** One merchant registration path; mount or delete the unused home pieces.

### P2

#### P2-1 — Product delete and admin role change have no confirm

- **Severity:** P2
- **Title:** Destructive actions are one click
- **Affected routes:** `/products`, `/users`
- **Files:** `components/products/ProductTable.tsx` (`onDelete` immediate); `apps/admin-panel/app/users/page.tsx` (role `<select>` mutates on change, including `ADMIN`)
- **Why it matters:** Accidental delete or privilege change has no undo in the UI. Vendor suspend does use `window.confirm`; product delete does not.
- **Suggested fix direction:** Confirm (or undo toast) before delete and before promoting/demoting roles.

#### P2-2 — Admin settings can submit seed defaults before load

- **Severity:** P2
- **Title:** Pricing form is editable before `admin.settings.get` returns
- **Affected routes:** `/settings`
- **Files:** `apps/admin-panel/app/settings/page.tsx` (`emptySettings` then `useEffect` hydrate; no `isLoading` gate)
- **Why it matters:** A fast Save can persist hardcoded fallbacks over live platform fees.
- **Suggested fix direction:** Disable the form until settings resolve, and show fetch errors.

#### P2-3 — Store and product pages degrade silently

- **Severity:** P2
- **Title:** Unknown store slug still renders “Store”; browse has no zero-results copy
- **Affected routes:** `/shop/store/[slug]`, `/shop/browse`, `/shop/product/[id]`
- **Files:** `app/shop/store/[slug]/page.tsx` (`shop?.storeName ?? 'Store'`; empty `grid-cols-4` if no items); `app/shop/browse/page.tsx` (no empty state; mixes live + mock); `app/shop/product/[id]/page.tsx` (falls back to `findMockProduct`, then “This listing is not available.”)
- **Why it matters:** A bad slug is not a 404. Filtered browse can show a heading and a blank grid. Home `ProductRail` hides empty sections (`return null`), so a failed live catalog plus empty mocks can make the mall look blank with no explanation.
- **Suggested fix direction:** Explicit not-found for unknown shops; “No matches” on browse; don’t hide every empty rail without a page-level empty.

#### P2-4 — Shopper header logo link is weakly named

- **Severity:** P2
- **Title:** Bag image `alt=""`; wordmark carries the name
- **Affected routes:** All `GuestChrome` pages
- **Files:** `components/shop/GuestChrome.tsx` (`<img src="/mmall-bag.png" alt="" />` next to wordmark `alt="M-MALL"`). Auth chrome does set `aria-label="MMall home"` on the same pattern (`components/auth/AuthChrome.tsx`).
- **Why it matters:** Inconsistent. If the wordmark fails to load, the header home control has no accessible name.
- **Suggested fix direction:** Same `aria-label` on the mall header lockup as on `AuthChrome`.

#### P2-5 — Footer date range and mock catalog mixing

- **Severity:** P2
- **Title:** Footer says “2027–2035”; home injects mock products beside live API data
- **Affected routes:** All mall pages (footer); `/shop` home
- **Files:** `components/shop/GuestFooter.tsx`; `app/shop/page.tsx` (`[...live.items, ...mockFeatured()]`)
- **Why it matters:** Copyright line is in the future relative to 2026. Mixing mocks with live listings trains shoppers on products that cannot be charged (`checkout` explicitly: “Demo listings cannot be charged through PayGate.”).
- **Suggested fix direction:** Current year (or omit range); gate mocks behind a demo flag and label them.

#### P2-6 — Vendor/admin MetricCard and BrandLockup duplicated

- **Severity:** P2
- **Title:** Parallel components drift between the two Next apps
- **Affected routes:** Vendor `/` vs admin `/dashboard`; both sidebars
- **Files:** `apps/vendor-dashboard/components/dashboard/MetricCard.tsx` vs `apps/admin-panel/components/dashboard/MetricCard.tsx` (admin supports `change` percent and `subtext`); identical `BrandLockup.tsx` in both apps
- **Why it matters:** Shared-ui is RN-only, so Next apps copy-paste. Admin metric cards can show “% this week”; vendor cards cannot. Future visual fixes will fork.
- **Suggested fix direction:** A small web primitive package (or move tokens-only components into `packages/config` consumers) so desk chrome stays aligned.

#### P2-7 — Filter “shops” control is a count chip, not a name

- **Severity:** P2
- **Title:** Subcategory shop expander is easy to miss
- **Affected routes:** `/shop`, `/shop/browse` (filter dialog)
- **Files:** `components/shop/FilterBar.tsx` (button label `{n} shops`)
- **Why it matters:** The control that reveals shop checkboxes looks like a static count. No `aria-expanded` on that inner toggle.
- **Suggested fix direction:** Treat it as a disclosure (`aria-expanded`, “Show shops”).
